YOUR DATA, EXPLAINED

Privacy: what happens to your data?

This page explains what the website and its services receive, what they save, and what you can clear yourself. It is based on checks completed on November 26, 2026. Some provider systems could not be fully checked.

The main things to know

  • Your connection has an IP address: a network address used to send information back to your device. The services that deliver this website receive it.
  • Some records are saved: the website's hosting provider can keep security records containing IP addresses. Chat and phone services have their own records, explained below.
  • Chat messages leave your browser: sending a question sends it to the service answering it. Some services save message text.
  • Some features save data on your device: these include your previous homepage visit, game progress, and preferences. You can clear them in your browser.

What does Andrew's own server save?

Some website features use a server Andrew runs himself. This server, called the gateway, receives your IP address so it can reply and limit excessive requests.

The checked website logs now hide IP addresses before saving diagnostic messages (records used to troubleshoot problems). Request logging is also turned off in the server software described below.

A correction: some older website logs did contain IP addresses. Those files were checked and the addresses hidden during the review. Earlier statements that addresses had never been saved were wrong.

What this check covers: the website logging controls on the inspected server. It does not prove that no address is saved by a hosting provider, the operating system, another device, or a later configuration.

Technical details: server logging

The application-log formatters and process-output supervisor redact IPv4 and IPv6 addresses (the two common IP address formats) before writing diagnostics. Access logging is disabled in Uvicorn. Request logging and persistent error logging are disabled in nginx.

How does the server limit abuse and count activity?

Limiting repeated requests

The gateway creates a coded identifier from your IP address and stores it with request times to check for excessive use. It stores this identifier rather than the address itself. This still allows requests to be linked; it does not make them fully anonymous.

Entries outside the time window used for these limits are removed when new checks run.

Counting activity by region

The gateway saves broad regional totals and when they were updated. A temporary coded address value may also be held in memory to reduce repeated location lookups.

These totals measure service activity, not unique people. The estimated region can be wrong.

Technical details: coded identifiers

Abuse controls use keyed identifiers derived from client addresses in a rate-limit database. These are pseudonymous: the address is replaced, but activity can still be linked. The separate, short-lived value used for location lookups is an address hash held in memory.

What happens when you use chat or phone services?

Nemo: Andrew's privately hosted AI assistant

Your question passes through the gateway to the private computer running the AI model. The gateway saves troubleshooting records and a separate record of prompts, meaning the text sent to the AI, with coded client identifiers.

Some sensitive patterns, such as credentials, are hidden before prompts are saved. That does not remove every kind of personal information. Files are replaced as they reach a size limit, with up to seven backup files. There is no fixed promise to delete them after a certain number of days.

Phone service

Calls use a telephone provider and speech or voice services. Troubleshooting records can include caller details, written versions of speech, and parts of the assistant's replies. This service can retain personal information.

Class & Service Desk Bot: a separate Google-hosted service

The bot on the chat page sends your questions to Google Cloud. Debug messages that wrote questions into application logs were removed. Error logs now record only the type of error.

New technical request records, which can include your IP address, are sent to a separate log store set to keep them for seven days. The search service's user-event collection setting was also turned off. These changes do not prove that older question-bearing logs were immediately deleted, or that Google keeps no other records.

Technical details: Google-hosted chat

The checked Cloud Run revision is personal-chat-00028-8c6. The route cloud-run-requests-to-short-bucket sends request logs to cloud-run-requests-short, a log bucket (storage area) with seven-day retention. New request logs are excluded from the _Default bucket to avoid a second copy there.

Vertex AI Search user-event collection is off for personal-assistant-all. The audit's later addendum records these fixes as applied and verified on November 26, 2026. Rules that could copy logs at a parent folder or organization level, and Google's own internal storage, remain outside the project-level check. See the audit project record.

HOSTING REVIEW · NOVEMBER 26, 2026

What did the hosting-provider review find?

This website is hosted on Cloudflare Pages. Cloudflare receives connection details to deliver pages and protect the site.

The account review found no configured jobs exporting request logs and no separate request-log archives set up in the tools checked. This does not mean Cloudflare keeps no IP addresses. Its own security records are separate, as explained next.

Andrew coordinated the account inspection through Muse AI. ChatGPT / Codex compared the third report with the website source and official documentation; it did not independently repeat the signed-in account checks. The inspection did not change settings, export visitor records, or start a live log stream.

Technical details: what was checked
  • No Logpush jobs (configured log exports) were found at account or zone level.
  • No Log Explorer datasets (configured log archives) were found. The account listing used include_zones=true to include the account's zones, meaning the websites managed under it. This covered the question left by a denied direct zone request. Dataset-list documentation.
  • Pages Functions provides live debugging logs rather than saved log history, according to its logging documentation. The inspected room-sensor relay contains no explicit visitor-IP or console logging. This says nothing about storage in other provider systems.

These findings describe the configuration inspected that day. Later changes need another check. See the audit project notes.

What can the hosting provider still save?

Cloudflare can keep security records containing your IP address and details of individual requests. Some records cover only a sample of requests. The documentation used for the November 26 review described up to 31 days of history for these security tools on this site's Free plan.

The review could not establish one deletion deadline covering all of the provider's internal systems. It therefore cannot promise that every copy of an IP address is deleted after 31 days.

Technical details: security records and remaining questions

The documented history applies to Security Events and Security Analytics. It is separate from configured exports and archives. See Security Events documentation and Security Analytics documentation.

The account report found Web Analytics enabled and no configured Zaraz tools. Checks remained for which hostname the analytics tracking script belongs to, whether the Zaraz script is automatically added to pages, and the unreadable Logpull retention setting (a separate log-access feature). These are still unverified; the earlier findings do not settle them.

What about other providers and cookies?

Some features load fonts, code libraries, maps, or other content from outside services. Those providers receive connection details needed to answer your browser's requests. Each service has its own data practices.

Security features can also set cookies, small pieces of data stored in your browser. See Cloudflare's cookie documentation. The checks above do not establish that every feature is cookie-free or saves no personal data.

The checks of the Google-hosted chat do not cover all of Google's internal processing. Likewise, the hosting-provider review does not cover the separate chat or phone providers.

What can you clear in your browser?

  • Previous homepage visit: one saved date and time for this browser and device. This feature does not send that time to a server or identify you across devices.
  • Repair-shop progress: game progress saved on your device when browser storage is available.
  • Preferences and speed results: settings such as weather units and saved page-speed measurements.
  • Displayed chat history: some chat screens remember messages in your browser. Sending a question also sends it to the answering service.

To remove this data, use your browser's settings to clear site data for this website. Clearing your browser does not delete records already held by a server or provider. Some browser modes block local storage; supported features then continue without saving their state.

Text messages and optional website updates

Text messages use Twilio and phone carriers, which have separate message records and records of your permission to receive messages. See the SMS Privacy Policy, SMS Terms & Conditions, and optional website-update signup.
